# Production & Local Deployment Guide

This guide explains how to deploy Aegis GRC locally for testing and to Cloudflare (Pages + Workers + D1) for production environments—completely free of cost.

---

## 💻 1. Local Development Sandbox Setup

Aegis GRC includes a client-side database simulator fallback (`mockApi.ts`) that runs the entire software locally inside your browser's `localStorage`, requiring no database servers or cloud accounts.

### Step-by-Step Local Setup
1. **Verify Prerequisites:** Ensure you have **Node.js** (v18.0.0 or higher) installed on your computer.
2. **Install & Link Workspaces:** Run the unified setup command to install dependencies, clean old lock files, and build workspace packages:
   ```bash
   npm run setup
   ```
3. **Seed Local Database Tables:** Build the local database structure and seed the default compliance frameworks:
   ```bash
   npm run db:migrate
   ```
4. **Boot Dev Server:** Start both the Hono Workers backend API and the Vite React frontend client concurrently:
   ```bash
   npm run dev
   ```
5. **Open Application:** Open your browser and navigate to **`http://localhost:5173`**.
6. **Activate the Platform:** The app will detect a new installation and redirect you to the Setup Wizard page. Enter the default activation code **`123456`** and configure your Administrator profile to seed the threat libraries and access the dashboard.

## ☁️ 2. Cloudflare Production Edge Deployment

Follow these steps to deploy Aegis GRC to Cloudflare's serverless platform.

### Step 1: Create a Cloudflare D1 Database Instance
1. Log into your Cloudflare account via the command line:
   ```bash
   npx wrangler login
   ```
2. Execute the database creator command:
   ```bash
   npx wrangler d1 create enterprise-risk-assessment-db
   ```
3. Wrangler will output the database details:
   ```toml
   [[d1_databases]]
   binding = "DB"
   database_name = "enterprise-risk-assessment-db"
   database_id = "YOUR_PRODUCTION_DATABASE_UUID"
   ```
4. Open [wrangler.toml](file:///d:/Projects/Enterprise_Risk_Assessment_Platform/backend/wrangler.toml) in your code editor.
5. Replace the placeholder database UUID under the `[[d1_databases]]` block with the `database_id` value generated by wrangler.

### Step 2: Apply Migrations to Production D1
Apply your Drizzle relational schema definitions directly to the live D1 database instance in the Cloudflare cloud:
```bash
npm run db:migrate:prod
```

### Step 3: Deploy the Hono Worker API
Deploy the backend Workers API script to Cloudflare:
```bash
npm run deploy:backend
```
> [!NOTE]
> Wrangler automatically binds the Firebase Project ID (`personal-projects-82ee7`) as a public environment variable during the deployment task. You do not need to run manual wrangler secret commands.

### Step 4: Deploy the React Frontend via Cloudflare Pages
Deploy the client frontend using the Cloudflare Dashboard Web UI:

1. Log into your **[Cloudflare Dashboard](https://dash.cloudflare.com/)**.
2. Navigate to **Workers & Pages** -> Click **Create application** -> Select the **Pages** tab -> Click **Connect to Git**.
3. Authenticate with GitHub and select your repository.
4. Set the following build settings:
   * **Project name:** `enterprise-risk-assessment`
   * **Production branch:** `main`
   * **Framework preset:** `Vite`
   * **Build command:** `npm run build`
   * **Build output directory:** `dist`
   * **Root directory:** `frontend` (Change this to `frontend` to isolate client dependencies and bypass workspace caching bugs)
5. Click **Environment variables (advanced)** -> Add a variable `NODE_VERSION` set to `20` to ensure package building compatibility.
6. Click **Save and Deploy**. Cloudflare Pages will build and deploy the React application.

## 🧭 3. Routing & Custom Domain Setup

To ensure the React client frontend on Cloudflare Pages can communicate with the Hono Workers API under the same domain without CORS blockers:

1. **Add Custom Domain to Pages:**
   * Navigate to **Pages** -> Select your project -> **Custom domains** -> Add your domain (e.g. `grc.company.com`).
2. **Map Workers Route to the Same Domain:**
   * Navigate to your Worker (`enterprise-risk-assessment-api`) -> **Settings** -> **Triggers** -> **Routes** -> **Add Route**.
   * Set the route path to: `grc.company.com/api/*`
   * Select your Zone.
3. This routes all `/api/*` endpoints to the Worker, while all other assets are served by Pages on the same corporate domain, preventing CORS errors.

## 🛠️ Troubleshooting Common Errors

### Error: Permission Denied for `tsc` compiler (Build Error 126)
* **The Cause:** If you previously attempted to deploy with the root directory set to `/` and then changed it to `frontend`, Cloudflare's build cache may restore corrupt `node_modules` symlinks.
* **The Fix:** In the Cloudflare Pages dashboard, click the **three dots** next to the deploy button and select **Retry deployment** -> **Clear cache and deploy**. This forces a clean install.

### Error: Setup Wizard fails to complete / DB sync timeout
* **The Cause:** The backend D1 database migrations were not run, leaving Hono unable to resolve user queries.
* **The Fix:** Ensure you execute `npm run db:migrate:prod` to apply tables before deploying the backend.
